# 程序安装与手动更新

主程序、插件包、个人技能/预设和私人数据是四种不同寿命的内容。主程序包只携带运行资源，不包含模型凭据、会话、记忆或个人能力状态；升级主程序不替你迁移这些数据。

## 从固定提交打包

在可信开发终端中，从包含分发实现的完整本地 Git 提交构建。需要项目要求的 Go、Git 和已下载的模块缓存。构建不自动下载依赖，不读取未提交源码；当前仅生成本机 OS/架构的程序包。

```sh
COMMIT=$(git rev-parse HEAD)
timeout 330s go run ./cmd/luna-dist -commit "$COMMIT" -out /绝对路径/luna-candidate.tar.gz
```

默认身份为 `dev-<提交前12位>`；`-version` 可以指定构建身份，但不会创建 tag、GitHub Release 或推送内容。内部五分钟截止；输出路径必须不存在。需要提前获取模块时，可由开发者单独执行 `go mod download`。

打包器直接读取提交的 Git 对象，不使用工作树、checkout 钩子或本地 attributes；拒绝符号链接与子模块。独立临时目录构建，使用 `-trimpath`、`-buildvcs=false`、关闭 CGO 和自动模块下载。相同源码、工具链和模块缓存输入下，归档顺序、时间与模式固定；跨工具链不承诺字节一致。

程序包包含：

- `bin/luna`；
- `plugins/bin/` 中五个基础工具及可选 JSON 格式化工具的预编译二进制；
- `web/`、`plugins/ui/`、`LICENSE`；
- `release.json`：完整源码提交、版本、平台、数据格式版本与逐文件 SHA-256/大小/可执行标志。

嵌入的提示词、内置 preset、技能与记忆管理界面随二进制携带。用户安装的插件包不进入程序分发包。

## 安装到新目录

已有 Luna 可直接执行维护命令；源码用户也可将命令前缀替换为 `go run ./cmd/luna`。维护命令不启动 HTTP 服务、不加载模型配置。

```sh
luna version
luna release install -archive /绝对路径/luna-candidate.tar.gz -dest /绝对路径/luna-builds/candidate
luna release inspect -dir /绝对路径/luna-builds/candidate
```

父目录需已存在，目标目录必须不存在。安装校验平台、清单格式、数据格式、文件路径/大小/摘要，拒绝链接、未声明文件、重复项和残缺归档。失败清理本次候选，不覆盖旧安装。上限：1024 个文件、每文件 128 MiB、展开载荷 512 MiB、清单 256 KiB。摘要用于完整性和身份，不是作者签名：**只安装可信来源的程序包**。

首次使用没有旧二进制时，也可以将可信归档解压到新空目录，然后运行其中的 `bin/luna release inspect -dir ...`；不要把不可信归档当成安全的自动安装来源。

## 手动切换与回退

1. 查看“设置 → 安装与更新”，核对当前版本、提交、平台和数据格式；这里不联网检查远程版本。
2. 将候选安装到新目录并核对身份。安装本身不重启、不选择当前实例。
3. 备份实际使用的配置/数据目录，保留旧程序目录。使用自定义 `-sessions-dir`、`-state-dir`、`-config-file` 时也要分别保留这些位置。
4. 由你停止旧实例，再用相同的数据位置和读取根启动新目录中的程序，例如：

```sh
LUNA_HOME=/绝对路径/私人数据 /绝对路径/luna-builds/candidate/bin/luna -read-root /绝对路径/项目
```

5. 回退时停止候选，重新启动旧程序。**代码回退不等于数据回退**：旧程序可能忽略新的 scope 字段或拒绝新会话/记忆记录，因此必须确认其数据兼容性，必要时使用兼容版本的备份，不能让旧程序直接猜测处理新数据。

分发运行不需要 Go：宿主从清单锁定的六个文件复制临时代次到用户缓存，每次重载重新校验摘要，再握手与发布。缺失或损坏不会回退为源码构建，也不会写安装目录。源码运行保留原有构建式热重载。两种方式都沿用失败保旧、在途调用固定代次与进程清理。

隔离命令和可执行插件包仍需 Linux/Bubblewrap 等原有依赖；“不需要 Go”不代表移除了隔离依赖。没有自动更新器、远程二进制替换接口、安装脚本或静默数据迁移。
