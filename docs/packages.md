# 用户插件包

插件包把工具、技能、工作预设和界面资源作为一个可版本化的单位分发。它与 Luna 主程序版本分开：修改个人技能或升级一个包，不需要给 Luna 新打一个 tag。

## 使用流程

1. 打开“设置 → 能力 → 管理插件包”。管理能力默认启用；已安装包有各自独立的启停状态。
2. 选择本地目录或 Git 来源。本地路径需为绝对路径；Git 需为可无交互读取的 HTTPS 地址或本地仓库，并提供完整 commit（40/64 位）。不接受分支名作为固定版本，不自动使用用户凭据；私有仓库可先在可信终端检出，再按本地目录导入。
3. 点击“导入候选”。这里只读取清单与声明文件、建立不可变快照，不执行包内代码、不运行安装钩子、不安装依赖，也不自动启用。
4. 审阅来源、内容摘要、清单、声明的访问能力和文件预览，勾选确认后启用。可执行工具先在无项目、无状态、无网络的隔离环境中做协议握手；失败不会替换当前版本。
5. 带界面代码的版本必须另行确认信任。**同源 JavaScript 不是安全沙箱**，它能访问页面及本地 API；只启用可信作者的界面代码。

示例包位于 `plugins/packages/writing-helper/`，包含一个 Python 标准库文本统计工具、写作审阅技能和预设。导入其绝对路径即可试用；它不读取项目、不联网、不写插件状态，模型调用时仍需执行审批。没有实际调用模型是导入和启用的正常行为。

## 更新、回退和移除

- “准备导入更新”填入现有来源。修改本地源码后重新导入，或填写新的完整 Git commit，再审阅候选；旧版本不会在导入阶段自动切换。
- 启用绑定确切修订及预期当前修订，防止旧页面覆盖新选择。新增访问能力会出现在审阅中；界面代码和更换来源有独立确认。
- 在版本下拉框选择旧版，再确认切换即可回退。不同 `state_schema` 的版本不能直接切换，本版不猜测如何迁移插件私有数据。
- 停用/移除撤除后续运行的工具和资源，但不删除旧代码快照或用户状态。已经开始的运行继续使用原快照；如需立即终止，使用会话的停止按钮。
- 损坏或被改动的代码不能继续执行，但仍可停用。包界面 URL 包含修订值，避免升级后浏览器继续使用缓存中的旧模块。

包管理目录和应用自身配置属于可信基座，不应作为第三方工具的可写项目目录。包内容哈希用于识别修订和发现内容变化，不是对作者身份的数字签名。

## 清单

清单文件为 `luna-package.json`，未知字段会被拒绝。最小工具示例：

```json
{
  "format": 1,
  "id": "my-helper",
  "version": "0.1.0",
  "title": "我的助手包",
  "files": ["tools/helper.py"],
  "tools": [{
    "name": "echo",
    "description": "返回传入文本",
    "entry": "tools/helper.py",
    "interpreter": "python3",
    "input_schema": {
      "type": "object",
      "properties": {"text": {"type": "string", "maxLength": 8000}},
      "required": ["text"],
      "additionalProperties": false
    },
    "access": {},
    "timeout_seconds": 30
  }]
}
```

- `files` 是唯一复制清单，不扫描整个目录来猜测内容。拒绝越界、符号链接、常见凭据/私人会话文件；未声明的 `.env` 不会被复制。
- 无 `interpreter` 时入口必须可执行；支持固定的 `sh`、`python3`、`node`，需宿主已安装。固定 `args` 属于清单，不由模型决定；没有任意安装或构建命令字段。
- 工具全名为 `pkg_<包id>_<工具名>`。模型输入按清单 schema 实际校验，不只把 schema 交给提供方。
- schema 支持有界的 object、array、string、boolean、number、integer，以及 properties、required、items、enum、maxLength、maxItems。对象必须关闭额外属性；嵌套最多 6 层，每个对象最多 32 项。数字采用有界有限范围，超大精确值应通过字符串协议表达。不支持的关键字不会被静默忽略。

## 工具协议与权限

每次调用启动一个隔离进程，标准输入是一行 JSON，标准输出必须是一个 JSON 对象。不要向 stdout 写日志，诊断可写 stderr；二者共享 32 KiB 输出上限。

```json
{"protocol":1,"method":"describe"}
{"protocol":1,"tools":["echo"],"version":"0.1.0"}
```

```json
{"protocol":1,"method":"call","tool":"echo","arguments":{"text":"hello"}}
{"protocol":1,"result":"hello"}
```

失败可返回 `{"protocol":1,"error":"原因"}`。握手的工具名必须与相同入口声明的工具集合一致；可选的版本号若提供，必须与清单一致。

所有代码工具都需要 `exec` 权限。访问声明如下，默认全部关闭：

| 字段 | 行为 |
| --- | --- |
| `access.read` | 请求当前工作区只读挂载 |
| `access.write` | 必须同时请求读取；只挂载核准的 `write_dirs`，默认当前工作区首个目录 |
| `access.network` | 请求现有公网 HTTP(S)/CONNECT 代理，不提供宿主网络、私网、UDP 或裸套接字 |
| `access.state` | 空、`read` 或 `write`；请求包自己的状态目录，每次需额外范围审批 |

写目录在自动范围之外时要求单次范围批准。执行前还会重新核对包内容，审批期间改动代码不会使用旧批准执行新代码。执行始终使用 Bubblewrap 隔离，即使会话选择 Full access 也不会让包工具回退为宿主原生命令。包目录及其项目路径别名保持只读，环境不自动继承模型凭据。

需要状态访问时，请求中会出现宿主给定的 `state_dir`；它不是模型参数。私有状态在能力状态根的 `pkg-<id>/` 中，与代码快照分开。各版默认 `state_schema=1`，保持兼容的格式由包作者维护。

## 技能、预设和界面

- `skills` 声明 `skills/<name>` 目录，其 `SKILL.md` 必须列入 files，按现有 frontmatter 规则校验。运行名为 `pkg_<包id>__<技能名>`，带有包来源和修订，不覆盖个人学习库。运行中的技能读取保留已冻结的包修订。
- `presets` 使用现有运行选择结构，由包能力贡献到 `GET /api/setups`。禁用包会从新选择中移除资源；复制到个人目录后可以独立编辑，包升级不覆盖个人副本。
- `static` 只列出需要经 HTTP 提供的声明文件。工具源码不会因为在 files 中就自动成为网页资源。
- `panels` / `widgets` 指定 id、title、entry；widget 可有 source。entry 必须是 static 中的 JS 模块，source 必须是本包的声明资源。模块沿用 `mount(target, api)` / `unmount(target)` 契约；宿主负责容器、撤除和用户布局，不允许组件覆盖用户选择。

## 存储与边界

管理状态位于能力状态根的 `packages/`；代码在 `versions/<id>/<revision>/`，catalog 保存用户选择。上限：磁盘暂存与保留内容合计 32 个包标识（包括目录登记失败但代码快照已保留的候选）、每包 32 个保留修订；同一管理器的暂存发布串行检查配额，不能通过并发导入越过上限；原始及规范化后的清单均不超过 64 KiB、最多 128 个文件、单文件 32 MiB、总载荷 64 MiB。达到保留上限明确拒绝，不自动删除版本或用户数据。移除条目仍保留在目录历史中。

Git 传输使用独立临时裸仓库，60 秒截止，读取 blob 而不是 checkout，因此不执行检出过滤器与仓库钩子。载荷上限约束最终声明文件，不等同于 Git 对象传输总量上限；不应导入体量不受信任的任意仓库。本版不提供后台自动更新、依赖安装、市场账户、签名信任服务或状态迁移脚本。
