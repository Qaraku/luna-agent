# 私人数据备份与恢复

备份是显式的本地维护操作，不是聊天工具，也不在运行中的网页服务里执行。**归档可能包含模型凭据、完整会话、记忆、个人技能、预设、插件代码和插件状态；默认不加密，不上传，不打印文件正文。** 请保存到只有自己能访问的位置，不提交 Git，也不要把它当作插件包分享。

## 取得当前实例的位置计划

“设置 → 安装与更新 → 下载数据位置计划”调用只读 `GET /api/backup-plan`，记录这个实例实际使用的配置、数据、会话、状态与额外技能目录。它不包含凭据值，但包含私人路径，不建议公开。下载不会备份数据，更不会停止实例。

也可以从本地终端生成计划。使用与实例相同的 `LUNA_HOME` / XDG 设置和数据相关启动参数：

```sh
LUNA_HOME=/绝对路径/私人数据 luna data plan -out /私有目录/luna-data-plan.json
# 使用自定义路径时，按实际启动参数添加：
# -root /安装根 -sessions-dir /会话目录 -state-dir /能力状态根
# -config-file /配置文件 -skills-dir /额外技能目录
```

源码用户可将命令前缀 `luna` 替换为 `go run ./cmd/luna`。计划文件和输出文件都不覆盖已有文件。位置计划不根据版本号迁移旧数据；旧布局仍按应用同一套选择规则解析。

## 停机后备份

先停止所有使用这些数据的 Luna 实例，并停止外部编辑器/脚本写入这些文件，再执行：

```sh
luna data backup -plan /私有目录/luna-data-plan.json \
  -out /私有目录/backup.tar.gz -offline -include-private
luna data inspect -archive /私有目录/backup.tar.gz
```

`-offline` 是你对停止写入的确认；`-include-private` 确认接受归档内可能含凭据等私人内容。缺少任一个标志不会读写备份。当前版本还使用协作式进程锁：与运行实例共享配置/数据/状态/会话根时拒绝备份，但它**不能替代对旧版程序、外部编辑器或非协作脚本的停机确认**。额外技能和外部只读配置不要求在系统目录旁创建锁。

来源不是“递归复制整个数据根”：组合根列出配置三文件、工作区元数据、会话、个人技能、记忆文件、技能学习库、预设、包目录及 catalog 保留的包状态。旧 `-state-dir` 指向源码仓库时，不会把源码、`.runtime/luna`、临时插件进程或整个 `.runtime` 打进去。已移除包的保留状态仍会备份；catalog 损坏时明确拒绝，不能悄悄漏掉包状态。

额外 `-skills-dir` 作为你选定的技能目录单独保存。项目源文件不包含在备份里；工作区元数据中的原机路径会保留。缺失的可选来源和空目录都有记录，输出的文件数、字节数和缺失来源数只说明实际快照，不声称不存在的资料已保存。

快照逐文件记录摘要、大小和可执行位；复制时发现内容变化则失败。拒绝目录内符号链接、特殊文件、恢复目标交叠以及超限，不截断；根路径的可解析符号链接按真实位置处理，悬空链接拒绝。来源范围内不能存放备份输出，以免把归档自己复制进去。

上限为 4 GiB 内容、每文件 512 MiB、16384 个文件/目录条目、4 MiB 清单；命令有五分钟协作截止。文件系统阻塞调用不被承诺为可强制中断的物理快照。归档权限为 `0600`，目录为 `0700`。检查命令流式校验完整性，只输出版本、规模等摘要；摘要不是作者签名，仍应只恢复可信备份。

## 恢复到新目录

```sh
luna data restore -archive /私有目录/backup.tar.gz \
  -dest /绝对路径/全新数据目录 -include-private
```

目标父目录需存在，目标目录必须不存在。恢复先预留目标锁，校验格式、目录边界、条目、摘要及归档尾部；失败清理本次创建的候选，成功也**不启动程序、不修改环境变量、不覆盖旧资料**。恢复期间保留 `.luna-restore-pending`；进程异常中断而未清理候选时，普通启动/备份会明确拒绝该目录，应重新恢复到另一个新目录，不要删除标记来冒充完成。

恢复将原机分散路径规范为一个可用的 `LUNA_HOME`：配置在根目录、会话在 `sessions/`、能力数据在各自命名空间；不会把原机绝对路径作为写入目的地。源版本、数据格式和额外技能信息记录在 `luna-restored.json`。额外技能位于 `imported-skills/<编号>/`，按返回的 `extra_skills` 列表添加启动参数，例如：

```sh
LUNA_HOME=/绝对路径/全新数据目录 /程序目录/bin/luna \
  -read-root /你的项目 \
  -skills-dir /绝对路径/全新数据目录/imported-skills/1
```

没有额外技能时不要添加示例中的 `-skills-dir`。按需恢复原有地址、项目规则等非数据启动参数；在新机器上检查工作区路径。备份含已审阅包及启用偏好，下次主动启动可能恢复这些可信包；恢复命令本身不运行包代码。会话保存的权限偏好仍不是本进程执行授权，审批提升不从备份恢复。

## 格式与锁文件

当前数据格式为 1。程序完成旧/新位置选择后，锁住所选根，再检查或创建根内的 `.luna-data-format.json`；遇到未知/较新格式拒绝启动或备份，不覆盖标记。标记随目录复制保留，归档用自己的数据格式字段携带这项约束，恢复时重新建立标记。

锁文件在相应根的父目录，以 `.luna-data-<路径摘要>.lock` 命名；进程退出释放锁，但不删除文件，避免删除后另一个进程锁住不同 inode。文件存在不代表进程仍存活，不要在运行中删除锁来绕过互斥。这些生成文件已被 Git 忽略。

**代码回退不等于数据回退。** 更旧的程序可能根本不认识格式标记，或不能正确理解新的记忆作用域、纠错、会话记录。降级应使用与该程序兼容的备份，而不是期待新标记控制一个没有实现它的旧程序。当前不执行自动数据迁移、清理或密钥轮换。
