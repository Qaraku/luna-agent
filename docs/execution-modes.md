# 会话权限与逐次审批

Luna 把**能力是否启用**、**当前会话的权限策略**和**本次操作的范围**分开。权限入口只在 composer 底边显示简短摘要；点击后查看矩阵、项目目录、自动写入范围和网络边界，不把这些内容永久铺在输入区。

## 默认策略

| 模型操作 | 默认 | 可选策略 |
|---|---|---|
| 项目文件读取 | 允许 | 允许 / 询问 / 拒绝 |
| 项目文件修改 | 询问 | 允许 / 询问 / 拒绝 |
| 工具联网 | 询问 | 允许 / 询问 / 拒绝 |
| 命令执行 | 询问 | 允许 / 询问 / 拒绝 |

这里控制的是**模型工具**，不是关闭模型提供方连接、浏览器控制请求或 Luna 自己保存会话。已经进入对话或上下文的内容不会因为修改权限而消失。读取设为“询问 / 拒绝”后，不再自动注入项目规则文件；询问模式下可由显式文件操作请求批准。能力开关仍独立：终端、文件写入、网页读取等需要在“设置 → 能力”启用。

可以直接在弹层修改，也可使用命令：

```text
/permissions
/permissions network deny
/permissions write ask
/permissions exec=allow
/permissions --default
```

查看权限不会授权；点击“应用权限”或明确执行修改命令才保存。运行中可查看，但必须停止当前运行才能修改策略。模型消息中的同名命令不会被执行。

## 一次审批究竟允许什么

工具先检查参数、策略与范围。任一必需权限为“拒绝”时直接拒绝该调用；需要“询问”或额外写入范围时，**在副作用发生之前暂停**，正文显示审批卡：

- 文件操作列出目标、写入内容预览和参数绑定；批准仅适用于该次调用。
- 命令列出完整命令、工作目录、可读/可写目录及请求的权限；多个待问维度合并为一次审批。
- 不分析命令文字来猜它“是不是安全命令”。批准后仍由挂载集合与网络通道强制执行边界。
- 拒绝是可恢复的工具拒绝；停止、审批过期或服务结束不会执行待批操作。
- 审批不占用工具自己的执行超时，但仍占整轮运行预算。刷新页面可重新查询当前会话的待审批项，也可停止仍在运行的任务。

“设置 → 工作区”里的目录清单现在是**自动写入范围**。即使在该范围内，会话策略为“询问”时仍须审批；范围外的项目路径需要额外的单次范围批准。“拒绝”不能被目录批准覆盖，项目外路径也不能由这个批准救回。自动范围按运行准入快照使用，修改清单从下一轮生效。

## 受限命令的参数

`luna_run` 保留 `command`、`cwd`、`timeout_s`，新增：

| 参数 | 默认与效果 |
|---|---|
| `read` | 默认 `true`，项目只读挂载；`false` 时不挂载项目，省略 `cwd`，在私有 `/tmp/work` 执行 |
| `write` | 默认 `false`；`true` 只提出写入请求，不是授予权限 |
| `write_dirs` | 需要 `write:true`；最多 16 个项目相对目录，省略时请求当前工作目录可写 |
| `network` | 默认 `false`；`true` 请求公共 HTTP(S)/CONNECT 代理通道 |

例如，在允许的读取范围内运行检查、禁止写盘和联网；或者请求只写 `out/`、同时联网，都能独立表达。可写挂载天然也可读，因此 `write:true, read:false` 明确拒绝，不伪装成“只写不可读”。文件写入工具为生成差异同样需要读取原文件。

受限模式保持 Linux Bubblewrap 的用户、进程、网络等命名空间与 seccomp 边界。系统运行时只读；HOME 和临时目录私有，临时目录上限 512 MiB。只将核准的项目子目录改为可写挂载，不自动使用宿主用户配置、凭据或依赖缓存。

### 联网不是共享宿主网络

批准联网后仍保留独立网络命名空间。沙箱中的 helper 提供 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 及小写变量，通过本次命令专用的 IPC 通道交给宿主公共地址转发器；不继承宿主代理凭据。使用 HTTPS CONNECT 时 TLS 仍在命令与目标之间端到端进行。

- 拒绝回环、私网、链路本地、保留/转换地址和本机接口地址，不能借联网权限调用 Luna 的本地控制接口。
- 解析后核准 IP 并直拨该 IP，避免 DNS 重绑定；IPC 消息、块大小和连接数均有上限。
- 不提供直接套接字、UDP 或透明全协议网络；程序需要支持代理。绕过代理不会获得宿主网络。
- 命令结束、超时或停止时关闭对应转发连接；隔离不可用时绝不回退到宿主执行。

## Full access：独立的高级选择

展开“高级：Full access”，阅读说明、勾选确认后才能启用。它直接使用宿主 `/bin/sh -c` 和当前系统用户的文件/网络权限，允许工作区外目录、宿主及私网服务；**绕过细粒度沙箱限制，不是 root 提权，也不是安全沙箱**。命令的请求参数不能把 Full access 再变成受限沙箱，应改回矩阵策略。

两种模式均无交互式 stdin，执行超时默认 30 秒、最多 120 秒，stdout/stderr 合计保留 32 KiB。Full access 只自动提供必要的 PATH/HOME/TMPDIR，但已授予的文件访问可能读到凭据；环境清理不是访问控制。停止时清理其进程组，不能保证控制故意脱离进程组的程序。

## 授权与持久化

会话 JSONL 中的 `permissions` 和 `execution_mode` **只是偏好**。真正的提升授权位于当前服务进程的内存，绑定当前会话；修改或复制会话文件不会授予它。

- 刷新浏览器不撤销当前服务内的授权。
- 重启后，“允许写入/联网/执行”的提升授权降回“询问”，已保存的拒绝仍然保留。界面展示实际有效值，而不是把偏好冒充授权。
- Full access 偏好在重启后显示待确认；需重新确认或切回受限模式才能开始运行。
- 保存失败不产生授权。策略、审批消费、运行准入与撤销共用受保护的状态边界；运行中展示该轮真实快照。

## 接口与代码入口

- `GET /api/execution?session=<id>`：有效模式/矩阵、偏好、待确认标记及目录/网络范围。
- `POST /api/sessions/{id}/execution`：完整 `permissions` 矩阵加 `confirm_permissions:true`；或单独提交 `mode:full_access` 与 `confirm_full_access:true`。变更要求精确 Origin，运行中返回 `409`。
- `GET /api/approvals?session=<id>`：当前会话的待审批项。
- `POST /api/approvals/{id}`：仅提交 `run_id`、`session_id`、`decision:approve|deny`，不接收新的操作参数。身份不符、过期和重复消费不会执行操作。
- `internal/plugin/access.go`、`internal/httpapi/approvals.go`、`internal/plugins/terminal/`、`internal/netbridge/`、`internal/netpolicy/`。

宿主 Kernel、已安装能力及其源码仍是可信部分，不是由这套沙箱隔离的不可信插件。若允许任务改写 Luna 或能力源码，它们在构建、重载或下次启动后的行为也会改变；此类改动需要单独审查，不能把可写的宿主程序目录当作普通不可信数据区。

本文说明实现，不表示已经替用户启用能力或授予任何现有实例权限。
