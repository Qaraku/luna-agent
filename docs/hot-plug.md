# 动手体验热插拔：JSON 工具

这个例子可以直接使用，不需要配置模型服务。JSON 的格式化、压缩和校验由独立 Go 插件进程完成；面板和模型工具 `luna_format_json` 共用同一实现。

## 1. 启动并启用

从仓库根目录运行：

```sh
mkdir -p .runtime
go build -o .runtime/luna ./cmd/luna
./.runtime/luna
```

默认地址是 `http://127.0.0.1:3210`；若显式更改过 `-addr`，以打印的 `LISTEN_URL` 为准。

打开**设置 → 能力 → JSON 工具 → 启用**，再点击页头的 **JSON 工具**。它默认停用，启用偏好会保存；第一次处理或显式重载时才启动子进程。

点击“填入示例”，或输入：

```json
{"name":"Luna","id":900719925474099312345,"items":[1,2,3]}
```

选择“格式化”后点击“处理 JSON”，再切换“压缩”试一次。大整数不会经过浮点数转换，重复键和键顺序也不被重写。完成信息显示实际服务的版本、代次与 PID；面板输入和结果不写入会话或能力数据，不发送给模型服务。若由模型调用该工具，参数和结果仍会按既有规则进入会话记录与模型通信。

## 2. 修改真实实现并重载

源码入口是 [plugins/json_format/main.go](../plugins/json_format/main.go)。将：

```go
const prettyIndent = "  "
```

改为四个空格：

```go
const prettyIndent = "    "
```

可同时更新 `pluginVersion`，**但并非必须**：版本标签由插件自己报告，内核不限制某几个版本，同版本也可以重建。

在**设置 → 诊断 → 重载工具源码**选择 `luna_format_json`，点击“重建并重载”。回到 JSON 面板再次格式化：缩进应变为四个空格，插件 PID 和代次改变；宿主与未选择的其他工具不重启。页面本身不必刷新。

这不是内核里的预置分支：更改的是插件源码，重载编译并启动的也是这份源码。

## 3. 验证失败不会替换旧进程

建议只在临时项目副本中做故障演练：在 JSON 插件源码里制造一个语法错误，再重载它。重载会报构建失败，但已加载的旧插件仍可处理 JSON。修复源码后重新重载即可。

全量重载也是如此：所选实现全部构建、启动并验证后才发布，不会把一个更新到一半的集合交给新调用。正在执行的旧 RPC 调用仍固定到原代次，调用结束后才回收旧进程。

## 4. 停用与进程生命周期

在“能力”中停用 JSON 工具后，页头入口、面板资源路由和处理接口一起退出服务，后续模型运行也不再获得 `luna_format_json`；重新启用可恢复。

**停用能力不是卸载进程。** 已加载的注册进程由宿主管理和缓存，可在重载、超时、取消或宿主退出时终止；能力状态与进程代次是两个独立的状态轴。本例没有持久数据可清理，停用也不修改源码。

## 接口方式

在已启动的本地实例上也可以用接口操作；地址和 Origin 必须完全一致：

```sh
LUNA_URL=http://127.0.0.1:3210
curl --fail-with-body -sS -X POST "$LUNA_URL/api/plugins/json-format/enable" \
  -H "Origin: $LUNA_URL"
curl --fail-with-body -sS "$LUNA_URL/api/json-format/format" \
  -H "Origin: $LUNA_URL" -H 'Content-Type: application/json' \
  --data '{"text":"{\"n\":900719925474099312345}","mode":"pretty"}'
curl --fail-with-body -sS "$LUNA_URL/api/reload" \
  -H "Origin: $LUNA_URL" -H 'Content-Type: application/json' \
  --data '{"tool":"luna_format_json"}'
```

已启用时重复启用会返回冲突，直接跳到处理步骤即可。浏览器或模型都不能通过这些接口指定构建目录、可执行文件或 shell 命令。

## 限制与验证

- 输入最多 16 KiB，嵌套最多 64 层，输出最多 64 KiB；超限明确拒绝，不截断成不完整 JSON。格式化输出过大时可改用压缩模式。
- 子进程源码必须可信；独立进程不等于安全沙箱。本例没有文件或网络处理逻辑，也不是 Terminal 的 Full access 模式。
- 模型调用只在用户启用能力后可用，是否使用工具由模型决定；面板始终不调用模型。
- 自动化验证使用临时源码副本和真实插件进程，覆盖输出变化、失败回滚、启停路由、工具与面板共用实现，以及面板卸载取消请求；不等于对真实模型答案质量的验证。
